01 平台总览
============================================================

[平台总览-项目定位]
问题：智慧路灯数字孪生管理平台是什么？
问题：这个平台是做什么的？
回答：智慧路灯数字孪生管理平台是一个面向城市路灯管理的 WebGIS 可视化系统。项目由 Vue 前端大屏和 Spring Boot 后端服务组成，用于统一管理路灯设备、运行状态、告警、能耗、运维和地图点位。

[平台总览-核心特点]
问题：这个项目的核心特点是什么？
问题：智慧路灯平台有什么亮点？
回答：项目核心特点是“地图 + 设备 + 数据看板”结合。Cesium 三维地图展示道路发光线和路灯点位；总览大屏展示路灯总数、在线率、离线数、告警数、今日能耗、区域分布、异常占比和运行趋势；设备详情展示设备运行数据和最近日志。

[平台总览-前端页面]
问题：前端有哪些页面？
问题：平台前端包含哪些功能入口？
回答：前端提供登录注册、总览大屏、Cesium 三维地图、设备列表、设备详情、告警中心、能耗分析、运维中心、系统管理和 AI 小助理入口。这些页面共同支撑路灯监控、异常处理、能耗查看和系统管理。

[平台总览-后端能力]
问题：后端提供哪些能力？
问题：Spring Boot 后端负责什么？
回答：后端提供认证鉴权、设备查询、设备详情、大屏统计、天气、系统用户、操作日志和 AI 小助理接口。后端控制器负责 HTTP 接口，服务层负责统计和业务逻辑，JPA 实体对应数据库表。

[平台总览-一句话介绍]
问题：请用一句话介绍这个系统。
回答：智慧路灯数字孪生管理平台是一个结合 Cesium 三维地图、路灯设备管理、告警处理、能耗分析和运维管理的 WebGIS 可视化系统。

[平台总览-三句话介绍]
问题：请用三句话介绍这个平台。
回答：第一，平台由 Vue 前端大屏和 Spring Boot 后端服务组成，用于管理路灯设备、状态、告警、能耗、运维和地图点位。第二，平台通过 Cesium 三维地图展示道路发光线和路灯点位，通过大屏和图表展示运行状态。第三，平台预留 AI 小助理入口，后续可结合 RAG 知识库和实时接口增强问答能力。

02 系统架构
============================================================

[系统架构-总体结构]
问题：系统整体架构是什么？
问题：前端后端是怎么组成的？
回答：智慧路灯项目由 Vue 前端和 Spring Boot 后端组成。前端目录是 project，入口为 src/main.ts，路由在 src/router/index.js，总览大屏主页面为 src/OverviewApp.vue。后端目录是 lamp-service，启动入口为 src/main/java/com/example/lampservice/LampServiceApplication.java，默认服务端口为 8081。

[系统架构-前端模块]
问题：前端主要模块有哪些？
问题：OverviewApp.vue 负责什么？
回答：src/OverviewApp.vue 负责总览布局、导航切换、地图监控入口和跨模块状态协调。登录页在 src/views/LoginView.vue。设备、告警、能耗、运维、系统管理等模块放在 src/views。

[系统架构-前端拆分]
问题：前端拆分了哪些工具文件？
问题：AiAssistantPanel 是什么？
回答：前端已拆出 useDashboardData、useDashboardCharts、cesiumRuntime、cesiumMapHelpers、mapData、CesiumSceneControls 和 AiAssistantPanel。它们分别负责大屏数据、图表、Cesium 运行时、地图辅助函数、地图数据、地图控制按钮和 AI 小助理浮窗。

[系统架构-后端控制器]
问题：后端有哪些控制器？
问题：Spring Boot 后端有哪些模块？
回答：后端核心控制器包括 AuthController、DashboardController、DeviceController、WeatherController、SystemUserController、SystemLogController 和 AssistantController。它们分别负责认证、大屏统计、设备、天气、系统用户、操作日志和 AI 小助理接口。

[系统架构-核心服务]
问题：后端有哪些 Service？
回答：核心服务包括 DashboardService、JwtService、PasswordService 和 OperationLogService。DashboardService 负责大屏统计 SQL 和业务统计；JwtService 负责 JWT 创建和解析；PasswordService 负责密码加密和升级；OperationLogService 负责记录系统操作日志。

[系统架构-技术栈]
问题：项目技术栈是什么？
回答：项目技术栈包括 Vue 前端、Cesium 三维地图、ECharts 图表、Spring Boot 后端、JWT 鉴权、JPA 实体和数据库表映射。前端负责页面和可视化展示，后端负责认证、设备、统计、系统管理和 AI 小助理接口。

03 登录认证与权限
============================================================

[认证流程-JWT]
问题：登录认证是怎么做的？
问题：前端如何携带 token？
回答：登录成功后，后端返回 JWT。前端将 token 保存到 localStorage 的 smart_lamp_token。全局 fetch 拦截器在请求 /api/** 时自动带上 Authorization: Bearer <token>，用于让后端识别当前登录用户。

[权限规则-SpringSecurity]
问题：哪些接口需要登录？
问题：哪些接口需要管理员权限？
回答：后端权限规则为：/api/auth/captcha、/api/auth/login、/api/auth/register、/api/auth/reset-password 公开访问；/api/system/** 需要 SUPER_ADMIN 或 ADMIN 权限；其他 /api/** 需要登录访问。

[认证接口-验证码]
问题：验证码接口是什么？
回答：GET /api/auth/captcha 返回验证码 key、验证码和过期时间，用于登录、注册、重置密码前校验。

[认证接口-登录]
问题：登录接口是什么？
问题：登录需要哪些字段？
回答：POST /api/auth/login 用于用户登录，请求字段包括 username、password、captchaKey 和 captcha。登录成功后返回 token 和 user。

[认证接口-注册重置]
问题：注册接口是什么？
问题：重置密码接口是什么？
回答：POST /api/auth/register 用于注册新用户，用户名需要 3 到 32 位字母、数字或下划线，联系方式支持手机号或邮箱。POST /api/auth/reset-password 用于重置密码，重置前需要验证码校验。

04 大屏总览与核心指标
============================================================

[大屏总览-页面作用]
问题：总览大屏有什么作用？
问题：智慧路灯大屏展示什么？
回答：总览大屏用于集中展示路灯系统运行状态，包括路灯总数、在线设备、离线设备、告警设备、今日能耗、在线率、区域分布、异常占比、运行趋势、告警列表和地图监控入口。

[核心指标-设备状态]
问题：路灯总数是什么意思？
问题：在线设备和离线设备是什么意思？
回答：路灯总数表示系统接入设备总量。在线设备表示当前可通信设备。离线设备表示当前不可通信设备。告警设备表示存在异常的设备。今日能耗表示当天累计用电量。

[核心指标-计算口径]
问题：在线率怎么计算？
问题：亮灯率是什么意思？
回答：在线率等于在线设备除以路灯总数。亮灯率等于当前亮灯设备除以应亮灯设备。异常占比用于判断主要故障类型，例如电压异常、通信中断、灯具故障和能耗异常。

[大屏接口-核心接口]
问题：大屏接口有哪些？
回答：大屏接口包括 GET /api/dashboard/summary、GET /api/dashboard/area-distribution、GET /api/dashboard/area-heatmap、GET /api/dashboard/exception-ratio、GET /api/dashboard/running-trend?range=today、GET /api/dashboard/alarm-list?limit=20 和 GET /api/dashboard/today-energy。

[大屏接口-summary]
问题：/api/dashboard/summary 返回什么？
回答：GET /api/dashboard/summary 返回路灯总数、在线设备、离线设备、告警设备、今日能耗等核心指标。

[大屏接口-trend-energy]
问题：运行趋势和今日能耗接口是什么？
回答：GET /api/dashboard/running-trend?range=today 返回运行趋势，range 可为 today、7d、30d。GET /api/dashboard/today-energy 返回今日能耗柱状图和汇总指标。

05 Cesium 地图与点位
============================================================

[Cesium地图-地图作用]
问题：Cesium 地图有什么作用？
问题：三维地图展示什么？
回答：Cesium 地图用于展示智慧路灯的空间分布、道路发光线和灯杆点位。管理人员可以通过地图观察路灯位置和状态，区分在线、离线、告警和维护设备，并从空间角度发现同一路段或同一区域的异常情况。

[Cesium地图-加载流程]
问题：Cesium 地图加载流程是什么？
回答：前端加载 Cesium runtime 后，按顺序准备灯杆点位、道路 GeoJSON、地形和底图。优先使用 Cesium Ion 卫星影像无标签样式，失败时自动回退到备用底图，避免地图空白。

[Cesium地图-点位渲染]
问题：路灯点位怎么显示？
问题：不同状态的灯杆怎么区分？
回答：道路发光线和灯杆点位由前端实体渲染。灯杆根据状态显示不同图标，包括在线、维护、离线、告警。相机限制用于防止钻入地形或低角度穿模。

[Cesium地图-点位数据]
问题：灯杆点位来自哪里？
问题：Cesium 如何定位灯杆？
回答：地图中的灯杆点位来自道路两侧生成的经纬度数据。点位使用 lng 和 lat 字段定位，Cesium 使用 Cartesian3.fromDegrees(lng, lat) 转换。业务点位优先于底图标签。

[Cesium地图-地图排查]
问题：地图无底图怎么办？
问题：灯杆点位不可见怎么办？
回答：地图无底图时检查 Cesium Ion Token、网络访问、浏览器控制台和备用底图配置。灯杆点位不可见时检查灯杆 JSON、lng 和 lat 字段、Cesium runtime 是否加载成功，以及图层控制是否关闭了路灯点位。

06 设备管理与设备详情
============================================================

[设备管理-页面作用]
问题：设备管理有什么作用？
问题：设备列表能看什么？
回答：设备管理用于查看和筛选路灯设备列表，了解设备编号、设备名称、区域、道路、状态等基础信息。用户可以通过它快速定位在线、离线、告警或维护状态的设备。

[设备状态-定义]
问题：设备状态有哪些？
问题：在线、离线、告警、维护分别是什么意思？
回答：设备状态包括在线、离线、告警和维护。在线表示设备正常通信，数据可上报；离线表示设备长时间未上报或通信失败；告警表示设备存在电压、通信、灯具、能耗等异常；维护表示设备处于巡检、维修或升级状态。

[设备详情-内容]
问题：设备详情包含哪些数据？
回答：设备详情包括设备编号、状态、经纬度、电压、电流、功率、亮度、运行时长、温度、信号强度和最近日志。这些数据可以辅助判断设备是否正常运行，以及异常可能来自供电、通信、灯具、控制器或能耗采集。

[设备接口-列表搜索详情]
问题：设备接口有哪些？
回答：设备接口包括 GET /api/device?limit=1000、GET /api/device/search?keyword=xxx 和 GET /api/device/{id}/detail。设备列表支持 keyword、status、limit 参数；设备搜索最多返回 10 条结果；设备详情返回设备状态、经纬度和运行指标。

[设备详情-接口失败]
问题：设备详情接口失败怎么办？
回答：设备详情来自 /api/device/{id}/detail。如果接口失败，前端会显示地图点位里的基础信息，并提示详情加载失败。前端存在 mock 兜底能力，用于后端不可用时保持界面可预览，但正式环境应以数据库统计结果为准。

07 告警中心与工单
============================================================

[告警中心-页面作用]
问题：告警中心有什么作用？
回答：告警中心用于集中查看和处理路灯设备异常，包括电压异常、通信中断、灯具故障、能耗异常等。用户可以根据告警等级、告警类型、设备编号、区域、道路和时间定位问题，再进入设备详情核对运行数据。

[告警排查-通用流程]
问题：告警应该怎么排查？
问题：收到设备告警后怎么处理？
回答：告警排查应先在告警中心按告警等级筛选一级和二级告警，查看告警类型、设备编号、区域、道路和发生时间。然后进入设备详情，核对电压、电流、功率、亮度、温度、信号强度和最近日志。

[告警排查-集中告警]
问题：同一区域出现集中告警怎么办？
回答：如果同一区域出现集中告警，应优先排查配电箱、网关、通信链路和道路施工影响。集中告警通常不应只按单灯故障处理，而应从区域供电、网络和施工影响角度排查。

[告警排查-单灯异常]
问题：单个路灯告警怎么办？
回答：如果只有单灯异常，优先排查灯具、电源模块、控制器和接线端子。可以结合设备详情中的电压、电流、功率、亮度、温度、信号强度和最近日志判断异常方向。

[告警排查-通信类告警]
问题：通信中断告警怎么排查？
问题：设备信号异常怎么处理？
回答：通信类告警应先查看设备信号强度、最近上报时间和最近日志。若同一区域多台设备通信异常，优先排查网关、区域网络和通信链路；若单台设备通信异常，重点检查通信模块、SIM 卡或网络信号、控制器状态。

[告警排查-电压功率类告警]
问题：电压异常怎么排查？
问题：功率异常怎么排查？
回答：电压、电流或功率异常时，应进入设备详情核对电压、电流、功率、亮度、温度和最近日志。单灯异常优先检查灯具、电源模块、控制器和接线端子；同一区域多台异常时，优先排查配电箱、供电线路和区域供电侧问题。

[工单处理-字段与优先级]
问题：告警生成工单需要哪些信息？
问题：工单优先级怎么划分？
回答：告警生成工单时，应带上设备编号、设备名称、区域、道路、告警类型、告警等级、发生时间和最近日志。高优先级包括一级告警、主干道照明中断、大面积离线；中优先级包括二级告警、局部道路照明异常、通信不稳定；低优先级包括单灯轻微异常、固件升级、常规巡检。

08 离线设备排查
============================================================

[离线排查-通用流程]
问题：设备离线应该怎么排查？
问题：离线设备怎么处理？
回答：离线设备应优先检查供电状态、网关通信、SIM 卡或网络信号、控制器运行状态和最近上报时间。排查时应结合设备详情、最近日志、区域分布和是否同一路段多台设备同时离线来判断。

[离线排查-多台同时离线]
问题：同一路段多台设备同时离线怎么办？
回答：同一路段多台设备同时离线，通常不是单灯故障，更可能是通信网关、配电箱、区域网络或供电侧问题。应优先检查网关、配电箱、区域网络、供电线路和是否存在道路施工影响。

[离线排查-单台离线]
问题：单台路灯离线怎么办？
回答：单台设备离线时，优先检查控制器、通信模块、SIM 卡或网络信号、设备供电和最近上报时间。若设备有最近日志，应结合日志判断是通信失败、供电异常还是设备控制器问题。

[离线排查-客户回复事实]
问题：客户反馈设备一直离线，需要哪些信息？
回答：处理客户反馈的设备离线问题时，需要获取设备编号、所在区域、道路位置和最近异常时间。排查方向包括供电状态、通信网关、SIM 卡或网络信号、控制器运行状态、最近上报时间，以及是否存在同一路段多台设备同时离线。

09 能耗分析
============================================================

[能耗分析-页面作用]
问题：能耗分析有什么作用？
问题：能耗分析页面能看什么？
回答：能耗分析用于观察路灯用电变化、今日能耗、运行趋势、区域能耗热力和异常能耗情况。它可以帮助管理人员发现异常常亮、调光策略失效、单灯功率异常和采集数据缺失等问题。

[能耗排查-能耗升高]
问题：能耗升高怎么排查？
问题：能耗异常升高是什么原因？
回答：能耗升高时，先对比昨日同小时曲线、亮灯率、平均功率和区域热力。若亮灯率不变但能耗升高，重点检查异常常亮、调光策略失效、单灯功率异常和传感器误报。

[能耗排查-能耗下降]
问题：能耗下降过快怎么排查？
回答：能耗下降过快时，需要确认是否存在大面积离线、误关灯、调光策略过低或采集数据缺失。能耗下降不一定代表节能效果，也可能说明设备异常、通信异常或数据采集异常。

[能耗接口-today-energy]
问题：今日能耗接口能做什么？
回答：GET /api/dashboard/today-energy 返回今日能耗柱状图和汇总指标，可用于展示当天不同时间段的能耗变化。

10 运维中心与系统管理
============================================================

[运维中心-作用]
问题：运维中心有什么作用？
回答：运维中心用于承接告警处理、巡检、维修、升级和工单流转等业务。它可以结合设备编号、设备名称、区域、道路、告警类型、告警等级、发生时间和最近日志，帮助运维人员安排处理优先级。

[系统管理-作用]
问题：系统管理有什么作用？
回答：系统管理用于管理系统用户和操作日志。系统用户管理需要管理员权限，操作日志用于记录系统操作行为，便于后续审计和问题追踪。

[系统管理-接口]
问题：系统管理接口有哪些？
回答：系统管理接口包括 GET /api/system/users、POST /api/system/users 和 GET /api/system/logs。这些接口需要管理员权限。

11 AI 小助理与 RAG 规划
============================================================

[AI小助理-入口]
问题：AI 小助理在哪里？
问题：前端 AI 助手组件是什么？
回答：AI 小助理入口在前端右下角，组件为 src/components/overview/AiAssistantPanel.vue。它可以作为后续智能问答入口，用于回答平台功能、设备状态、告警排查、能耗分析和系统使用问题。

[AI小助理-接口]
问题：AI 小助理接口是什么？
问题：/api/assistant/chat 怎么用？
回答：AI 小助理接口为 POST /api/assistant/chat，请求字段包括 question 和 messages。当前返回规则型答案，后续接入 RAG 时，可以返回 answer、sources 和 createdAt，其中 sources 对应知识库片段来源。

[AI小助理-当前阶段]
问题：AI 小助理现在是什么状态？
问题：AI 小助理现在是否已经接入 RAG？
回答：当前 AI 小助理接口为规则型答案。RAG 知识库已经有雏形，整理了系统架构、接口说明、Cesium 地图排查、告警处理、离线设备排查、能耗分析和智慧路灯业务知识。后续可以接入向量数据库，让小助理基于项目文档和运行数据回答问题。

[RAG规划-处理流程]
问题：RAG 接入后流程是什么？
问题：后续 AI 小助理怎么接 RAG？
回答：RAG 接入后的推荐流程为：用户问题 -> 关键词/向量召回 -> 重排 -> 拼接上下文 -> 大模型生成 -> 返回答案和引用来源。小助理应优先检索本知识库，再结合实时接口数据回答。

14 办公生成事实素材
============================================================

[办公素材-项目介绍]
问题：生成项目介绍时可以依据哪些事实？
回答：可依据这些事实生成项目介绍：项目名称为智慧路灯数字孪生管理平台；项目由 Vue 前端大屏和 Spring Boot 后端服务组成；核心功能包括 Cesium 三维地图、设备管理、设备详情、告警中心、能耗分析、运维中心、系统管理和 AI 小助理；技术特点包括 JWT 鉴权、ECharts 图表、JPA 实体、mock 兜底和 RAG 规划。

[办公素材-日报]
问题：生成日报时可以依据哪些事实？
回答：可依据平台资料生成日报内容，包括整理知识库、梳理前端大屏、Cesium 地图、设备管理、告警中心、能耗分析、系统管理、AI 小助理、后端接口、运维排查和 RAG 规划等工作。

[办公素材-客户回复]
问题：生成客户回复时可以依据哪些事实？
回答：客户反馈设备离线时，可依据离线排查事实组织回复：需要核查供电状态、通信网关、SIM 卡或网络信号、控制器运行状态、最近上报时间，并收集设备编号、区域、道路位置和最近异常时间。

[办公素材-PPT大纲]
问题：生成 PPT 大纲时可以依据哪些事实？
回答：PPT 大纲可围绕项目背景、建设目标、系统架构、核心功能、接口能力、运维价值、AI 小助理和后续 RAG 规划展开。核心功能包括总览大屏、Cesium 地图、设备管理、告警中心、能耗分析、运维中心、系统管理和 AI 小助理。
