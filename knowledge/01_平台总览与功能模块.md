# 平台总览与功能模块

## 文档边界

本文只说明平台“有什么”，包括平台定位、功能模块、技术栈、角色、架构和能力边界。具体“怎么使用”见 `02_平台使用说明.md`。

## 项目定位

智慧路灯数字孪生管理平台是面向城市智慧照明管理的 WebGIS 平台，用于集中展示路灯设备状态、地图点位、告警情况、能耗趋势、运维工单和系统管理信息。

平台核心目标是把路灯设备、地理空间、运行状态和运维流程放到同一个可视化界面中，辅助管理人员快速了解城市照明运行情况，定位异常设备，并进行告警处理和运维调度。

## 平台名称

平台界面显示名称为“曙光智慧照明”，副标题为“智慧路灯数字孪生平台”。系统管理页面中的平台名称为“曙光智慧照明数字孪生平台”。

## 项目目录结构

- `project`：前端项目目录。
- `project/src/main.ts`：前端入口文件。
- `project/src/router/index.js`：前端路由配置。
- `project/src/OverviewApp.vue`：平台主界面和总览大屏入口。
- `project/src/views`：设备、告警、能耗、运维、系统管理等业务页面。
- `project/src/components/overview`：总览大屏、地图面板、AI 小助手等组件。
- `project/src/utils`：API 请求、Cesium 加载、地图数据处理等工具。
- `lamp-service`：Spring Boot 后端项目目录。
- `lamp-service/src/main/java/com/example/lampservice/LampServiceApplication.java`：后端启动入口。
- `docs/dify_knowledge`：准备上传到 Dify 的正式知识库资料目录。

## 用户角色

平台中的角色包括：

- `SUPER_ADMIN`：超级管理员。
- `ADMIN`：管理员。
- `OPERATOR`：运维人员。
- `VIEWER`：普通用户或观察角色。

登录成功后后端返回 JWT，前端保存到 `localStorage` 的 `smart_lamp_token`。后续访问 `/api/**` 接口时，前端会自动携带 `Authorization: Bearer <token>`。

## 已实现核心能力

### 登录注册与权限

平台提供登录、注册、验证码、重置密码、JWT 鉴权、系统用户管理和操作日志能力。

### 总览大屏

总览大屏用于展示平台整体运行状态，包括：

- 路灯总数
- 在线设备
- 离线设备
- 告警设备
- 今日能耗
- 区域分布
- 区域热力分布
- 异常占比
- 运行趋势
- 告警列表
- 今日能耗分析

### 地图监控

地图监控基于 Cesium 展示路灯点位、道路发光线、告警点位和区域定位。地图支持 2D、3D、全屏切换，并根据路灯状态展示不同样式。

已实现或已接入的地图能力包括：

- 地图总览
- 路灯点位
- 告警点位
- 图层控制
- 区域定位
- 2D / 3D / 全屏切换
- 点位点击查看设备信息
- GeoServer WFS 道路数据加载失败时的兜底处理

### 设备中心

设备中心用于查看路灯设备资产和运行状态。

已实现或已接入的能力包括：

- 设备列表
- 设备详情
- 设备搜索
- 设备状态筛选
- 设备日志
- 远程控制演示页面

设备状态主要包括在线、离线、告警、维护。

### 告警中心

告警中心用于查看和处理异常事件。

已实现或已接入的能力包括：

- 告警总览
- 实时告警列表
- 告警记录
- 告警详情查看
- 告警筛选
- 告警转运维工单的业务流程说明

告警类型包括灯具故障、通信中断、电压异常、能耗异常、亮度异常、设备离线等。

### 能耗分析

能耗分析用于查看照明系统用电情况和节能效果。

已实现或已接入的能力包括：

- 能耗总览
- 趋势分析
- 区域能耗排行
- 设备能耗排行
- 异常能耗设备识别
- 能耗异常工单生成演示

### 运维中心

运维中心用于承接告警、设备巡检、设备维修、固件升级和能耗异常等任务。

已实现或已接入的能力包括：

- 工单列表
- 工单筛选
- 工单详情
- 告警处理工单
- 设备巡检工单

- 固件升级工单
- 能耗异常工单

### 系统管理

系统管理用于维护平台用户、角色、参数和日志。

已实现或已接入的能力包括：

- 用户管理
- 角色权限展示
- 系统参数
- 操作日志
- 用户启用、禁用、重置密码等管理操作

### AI 助手

AI 助手用于回答智慧路灯平台的功能说明、设备运维、告警处理、能耗分析、地图排障、后端接口和部署运维问题。

当前 Dify 版本通过 Dify 应用嵌入到 Vue 前端页面中，知识库资料来自 `docs/dify_knowledge` 目录中的 Markdown 文档。

后续规划包括：

- 使用 Dify Chatflow 对用户问题进行分类。
- 使用知识库检索回答平台说明、设备排查、告警处理和部署问题。
- 使用 HTTP Request 节点调用 Spring Boot 后端接口，查询设备、告警、能耗等业务数据。
- 后续可扩展自定义 Vue 聊天窗口和后端代理 Dify API。

## 数据流概览

平台典型数据流如下：

1. 用户登录平台。
2. 前端保存 JWT。
3. 用户进入总览、地图、设备、告警、能耗等模块。
4. 前端通过 `/api/**` 请求后端接口。
5. 后端从数据库或业务服务中查询设备、统计、日志、用户等数据。
6. 前端将数据渲染为卡片、表格、图表、地图点位和详情面板。
7. 用户根据告警、离线、能耗异常等信息进入设备详情或运维流程。
8. AI 助手通过 Dify 知识库回答平台说明、排障流程和使用问题。

## 项目亮点

- 使用 Cesium 构建智慧路灯数字孪生地图场景。
- 将设备状态、告警、能耗、工单和地图点位统一到同一个平台。
- 前端采用大屏式科技风界面，适合城市运行监控场景。
- 后端具备 JWT 鉴权、用户管理、操作日志、设备接口和总览统计接口。
- Cesium 地图具备底图回退能力，避免底图异常时页面完全空白。
- Dify 知识库资料按平台总览、使用说明、设备排查、告警流程、能耗分析、地图排障、接口字段和部署运维拆分，便于 AI 助手检索。
