# 部署运维与常见问题

## 文档边界

本文只整理部署、启动、Nginx、接口代理、数据库、GeoServer 和页面数据异常等运维问题。用户常见业务问答见 `09_常见问题FAQ.md`。

## 前端本地启动

前端项目目录：

- `project`

启动命令：

```bash
npm install
npm run dev
```

默认开发地址：

- `http://localhost:3000`
- `http://127.0.0.1:3000`

Vite 配置中开发端口为 3000。

## 前端打包

打包命令：

```bash
npm run build
```

打包产物目录：

- `project/dist`

部署时将 `dist` 内容放到 Nginx 静态资源目录。

## 前端代理

开发环境 Vite 代理：

- `/api` 默认代理到 `http://localhost:8081`
- `/geoserver` 默认代理到 `http://localhost:8080`

可通过环境变量调整：

- `VITE_API_PROXY_TARGET`
- `VITE_GEOSERVER_PROXY_TARGET`

## 后端本地启动

后端项目目录：

- `lamp-service`

启动入口：

- `LampServiceApplication.java`

默认端口：

- `8081`

启动命令：

```bash
./mvnw spring-boot:run
```

Windows 环境可使用：

```bash
mvnw.cmd spring-boot:run
```

## 后端配置

主要配置文件：

- `lamp-service/src/main/resources/application.properties`
- `lamp-service/src/main/resources/application-dev.properties`

重要配置项：

- `SERVER_PORT`：后端服务端口，默认 8081。
- `DB_URL`：数据库连接地址。
- `DB_USERNAME`：数据库用户名。
- `DB_PASSWORD`：数据库密码。
- `JWT_SECRET`：JWT 签名密钥。
- `FLYWAY_ENABLED`：是否启用 Flyway。

知识库中不要记录真实数据库密码、真实 JWT 密钥、服务器密码或 API Key。

## 数据库

后端默认使用 PostgreSQL。

开发配置中默认数据库地址为：

- `jdbc:postgresql://localhost:5432/smart_lamp`

如果数据库未启动或连接失败，后端可能无法正常启动。

## Nginx 部署建议

前端部署：

1. 在 `project` 目录执行 `npm run build`。
2. 将 `dist` 内容部署到 Nginx 静态资源目录。
3. 配置前端 history 路由回退到 `index.html`。

后端代理：

- 将 `/api` 反向代理到 Spring Boot 后端 `http://127.0.0.1:8081`。

GeoServer 代理：

- 将 `/geoserver` 反向代理到 GeoServer 服务，例如 `http://127.0.0.1:8080`。

## 前端启动失败

排查顺序：

1. 确认已经进入 `project` 目录。
2. 确认已执行 `npm install`。
3. 确认 Node.js 版本可用。
4. 确认 3000 端口未被其他服务占用。
5. 查看终端报错，优先处理依赖缺失、语法错误和环境变量错误。

## 后端启动失败

排查顺序：

1. 确认已经进入 `lamp-service` 目录。
2. 确认 JDK 17 可用。
3. 确认 8081 端口未被占用。
4. 确认 PostgreSQL 已启动。
5. 确认 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 配置正确。
6. 确认 `JWT_SECRET` 长度满足后端要求。
7. 查看 Maven 和 Spring Boot 启动日志。

## 后端接口连不上

排查顺序：

1. 检查后端是否启动在 8081 端口。
2. 检查前端 `/api` 代理是否指向后端。
3. 检查浏览器网络面板中的接口状态码。
4. 如果返回 401，检查登录 token 是否存在或是否过期。
5. 如果返回 403，检查用户角色权限。
6. 如果返回 500，查看后端日志和数据库连接。

## 页面能打开但数据不显示

优先检查：

- `/api` 反向代理是否正确。
- 后端是否启动。
- 数据库是否可用。
- 登录 token 是否有效。
- 接口是否返回 401、403 或 500。
- 前端是否触发接口请求。
- 浏览器控制台是否有 JavaScript 错误。

如果地图数据不显示，还要检查：

- `/geoserver` 代理。
- GeoServer 是否启动。
- 路灯点位 JSON 是否能加载。
- Cesium runtime 是否加载成功。

## GeoServer WFS 502

如果 `/geoserver` 请求返回 502，说明前端代理无法访问 GeoServer。

排查步骤：

1. 检查 GeoServer 是否启动。
2. 检查 GeoServer 端口是否为 8080。
3. 检查 `VITE_GEOSERVER_PROXY_TARGET` 是否正确。
4. 检查 WFS 图层名称和工作区是否正确。
5. 检查 Nginx 或 Vite 代理配置。
6. 即使 GeoServer 失败，前端也应继续加载本地路灯点位。

## 登录后跳回登录页

常见原因：

- token 不存在。
- token 过期。
- 后端 JWT 密钥不一致。
- 接口返回 401。
- 浏览器本地存储被清空。

排查建议：

- 检查 `localStorage` 中是否有 `smart_lamp_token`。
- 检查后端鉴权配置。
- 检查登录接口是否成功返回 token。
- 检查请求头是否携带 `Authorization: Bearer <token>`。

## Dify 助手接入注意事项

Dify API Key 不应写入前端代码或知识库文档。正式接入时建议：

- Dify 应用嵌入前端页面时，按 Dify 官方方式配置应用。
- 如果使用 Dify API，建议由 Spring Boot 后端代理调用。
- 后端代理负责保存 API Key、记录请求日志、处理异常和统一返回格式。
- Dify 知识库只存放适合回答问题的项目资料，不存放密钥、密码和完整源码。
