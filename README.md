# 智慧路灯数字孪生管理平台 AI 助手

> 基于 Dify 搭建的企业级 AI 助手示例，面向“智慧路灯数字孪生管理平台”提供知识库问答、运维排查、业务数据查询和结构化分析能力。

---

## 1. 项目简介

本项目是“智慧路灯数字孪生管理平台”的企业 AI 助手模块，基于 **Dify Chatflow** 搭建。

助手不仅可以基于项目资料进行知识库问答，还新增了 **HTTP Request 工具调用能力**，能够调用 Spring Boot 后端接口，读取 PostgreSQL 中的智慧路灯运行数据，并由 LLM 自动整理为面向运维人员的自然语言回答。

当前项目重点展示：

- Dify 知识库问答
- Chatflow 工作流编排
- System Prompt 行为约束
- 后端 API 工具调用
- PostgreSQL 业务数据查询
- 告警、离线设备、能耗异常的结构化总结
- 企业 AI 助手在 WebGIS 项目中的接入方式

---

## 2. 项目背景

智慧路灯数字孪生管理平台由 **Vue 前端大屏 + Spring Boot 后端服务 + PostgreSQL/PostGIS 数据库** 组成，核心目标是对城市路灯设备、运行状态、告警、能耗、运维和地图点位进行统一管理。

平台已有能力包括：

- 登录注册
- 总览大屏
- Cesium 三维地图
- 设备列表与设备详情
- 告警中心
- 能耗分析
- 运维中心
- 系统管理
- AI 小助理入口
- JWT 鉴权
- mock 兜底能力
- 后端业务接口
- PostgreSQL 数据库存储

本项目在此基础上，将项目资料整理为 Dify 知识库，并通过工作流接入后端 API，使 AI 助手具备“资料问答 + 实时业务查询”的能力。

## 4. 核心能力

### 4.1 知识库问答

助手可以回答智慧路灯平台相关问题，例如：

```text
你是谁？
你能做什么？
智慧路灯数字孪生管理平台有哪些功能？
系统整体架构是什么？
前端有哪些页面？
后端有哪些接口？
Cesium 地图在项目中有什么作用？
设备离线应该怎么排查？
能耗异常应该怎么分析？
```

### 4.2 后端 API 工具调用

助手可以通过 Dify HTTP Request 节点调用后端接口，例如：

```text
今天有什么告警？
今天有哪些异常？
当前有多少离线设备？
今天有哪些能耗异常？
哪些设备需要巡检？
```

工作流会自动调用：

```http
GET /api/ai/today-exceptions
```

接口返回今日异常、告警、离线设备、能耗异常和异常明细，LLM 节点再将 JSON 数据整理为适合企业系统展示的回答。

### 4.3 办公内容生成

助手还可以基于项目资料生成：

```text
平台产品介绍
项目日报
客户回复
PPT 大纲
运维说明
接口说明
排查流程
```

### 4.4 边界控制

对于资料中不存在的问题，助手会进行边界说明，避免编造：

```text
平台价格是多少？
公司有哪些客户案例？
公司创始人是谁？
```

## 6. 工作流设计

### 6.1 总体流程

```text
用户输入
↓
Dify Chatflow
↓
问题分流
├── 平台资料类问题 → 知识库检索 → LLM → 直接回复
└── 今日异常/告警/离线/能耗异常 → HTTP Request → 后端 API → LLM 总结 → 直接回复
```

### 6.2 知识库问答分支

```text
用户问题
↓
知识检索
↓
LLM 根据知识库上下文回答
↓
直接回复
```

适用于：

- 平台介绍
- 系统架构
- 前端页面
- 后端接口
- Cesium 地图
- 告警处理流程
- 离线排查流程
- 能耗分析说明
- 部署运维说明

### 6.3 API 工具调用分支

```text
用户问题
↓
HTTP Request 节点
↓
GET /api/ai/today-exceptions
↓
Spring Boot 查询 PostgreSQL
↓
返回今日异常 JSON
↓
LLM 节点总结统计与明细
↓
直接回复
```

适用于：

- 今天有什么告警？
- 今天有哪些异常？
- 当前有多少离线设备？
- 今天有哪些能耗异常？
- 哪些设备需要巡检？

## 9. 知识库设计

### 当前知识库版本


知识库采用“事实知识库”设计，只保存项目事实，不把大量行为指令、测试问题、面试表达和长篇办公模板直接放进知识库。

知识库主要包含：

- 平台定位
- 核心功能
- 前端页面
- 后端能力
- 系统架构
- 登录认证
- 大屏接口
- 设备接口
- Cesium 地图说明
- 设备状态与设备详情
- 告警中心
- 离线排查
- 能耗排查
- 地图异常排查
- 系统管理
- AI 小助理与 RAG 规划
- mock 兜底与实时数据边界

### 迭代过程

| 版本 | 说明 |
|---|---|

## 10. Prompt 设计

### 10.1 System Prompt 目标

System Prompt 用来控制助手行为，而不是和事实资料混在知识库中。

主要约束包括：

1. 助手身份为“智慧路灯数字孪生管理平台 AI 助手”
2. 回答必须优先基于知识库和接口返回结果
3. 不允许编造知识库或接口中没有的技术栈、数据、设备状态和商业信息
4. 资料外问题需要说明“当前资料中没有找到相关信息”
5. 实时数据类问题优先调用后端 API
6. 办公生成类问题可以基于知识库事实生成结构化内容
7. 回答应简洁、准确、适合企业系统展示

### 10.2 今日异常总结 Prompt

```text
你是智慧路灯数字孪生管理平台的企业 AI 助手。

用户问题：
{{query}}

今日异常接口返回：
{{body}}

请根据“今日异常接口返回”的数据，回答用户关于今日异常、告警、离线设备、能耗异常的问题。

回答要求：
1. 先总结今天异常总数。
2. 分别说明告警数量、离线设备数量、能耗异常数量。
3. 然后列出前 5 条异常明细。
4. 每条异常包含：类型、等级、设备编号、设备名称、区域、道路、状态、处理建议。
5. 只能依据接口返回数据回答，不要编造接口中没有的信息。
6. 如果接口返回为空，回答“当前接口未返回异常数据”。
7. 回答要简洁，适合企业系统助手展示。
```

## 18. 项目亮点

1. 基于真实 WebGIS 项目资料构建，不是通用聊天机器人。
2. 使用 Dify 知识库和 Chatflow 编排实现企业资料问答。
3. 将知识库事实和 System Prompt 行为规则分离，降低幻觉。
4. 接入 Spring Boot 后端 API，使助手具备业务数据查询能力。
5. 通过 PostgreSQL 数据返回今日异常、告警、离线和能耗异常信息。
6. 使用 LLM 将接口 JSON 自动整理为运维人员可读的结构化回答。
7. 支持资料问答、运维排查、办公生成和后端业务查询。
8. 具备继续嵌入 Vue WebGIS 系统的扩展路线。

## 19. 面试表达

> 因此这个项目不是单纯的知识库聊天机器人，而是一个结合 WebGIS 项目资料、Dify 工作流、后端 API 和数据库业务数据的企业级 AI 助手雏形。

## 20. 项目总结

本项目完成了一个基于 Dify 的智慧路灯企业 AI 助手。

项目从最初的知识库问答，逐步升级为支持后端 API 工具调用的业务型助手。当前助手已经可以回答平台资料、系统架构、运维排查和办公生成类问题，也可以通过 HTTP Request 节点调用后端接口，查询数据库中的今日异常、告警、离线设备和能耗异常数据，并生成结构化回答。

该项目可用于学习展示、项目演示、README 说明、简历项目包装和后续 WebGIS AI 助手扩展。
